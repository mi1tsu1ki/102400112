\# Coding Style Guide



本規範參考以下官方與主流業界規範：



\- Python：PEP 8

&#x20; https://peps.python.org/pep-0008/

\- JavaScript：Google JavaScript Style Guide

&#x20; https://google.github.io/styleguide/jsguide.html

\- HTML/CSS：Google HTML/CSS Style Guide

&#x20; https://google.github.io/styleguide/htmlcssguide.html

\- Git Commit：Conventional Commits

&#x20; https://www.conventionalcommits.org/



\## Python



\- 使用 4 個空白縮排。

\- 變數與函式使用 snake\_case。

\- 類別使用 PascalCase。

\- 常數使用全大寫與底線命名。

\- 函式應具備明確、單一的功能。

\- 適當加入例外處理與輸入驗證。

\- 優先使用清楚易讀的程式碼，避免過度複雜的單行寫法。



\## JavaScript



\- 變數與函式使用 camelCase。

\- 類別使用 PascalCase。

\- 使用 const 與 let，避免使用 var。

\- 優先使用嚴格相等運算子 ===。

\- 函式應維持單一職責。

\- 避免將過多邏輯集中在單一函式中。



\## HTML/CSS



\- HTML 使用語意化標籤。

\- CSS class 使用清楚且具描述性的名稱。

\- 避免大量使用 inline style。

\- 維持適當的縮排與區塊結構。

\- 表單欄位應提供清楚的標籤與提示。



\## Git



\- Commit message 使用 Conventional Commits 格式。

\- 常用類型包括：

&#x20; - feat：新增功能

&#x20; - fix：修正錯誤

&#x20; - docs：文件修改

&#x20; - refactor：重構

&#x20; - test：測試

&#x20; - chore：雜項設定

\- 每次 commit 應對應一個清楚且具體的修改目的。
